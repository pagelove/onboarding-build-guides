# From approved design to working app

Use this workspace supplement with the chosen design system or de-slop guidance.
Keep the private/pinned upstream source intact. An approved screenshot establishes
an approved visual direction, not functioning saving, authorization or updates.

Before implementation, record:

1. The visitor's situation and the questions the first screen must answer. For
   an explainer: what the product does, whom it helps, why it helps, and an example
   the visitor can understand without an account. Review this against the brief.
2. Approved copy, factual sources/dates, missing requested inputs and any fallback.
   Do not call an official-site fallback the latest Google Drive messaging.
3. Preserved colors, brand assets, personal fields, controls, routes and behavior.
   Resolve explicit current user choices against older DESIGN files and snapshots.
4. Exact deployment variant and user journeys: submit/save/reload, rejection and
   recovery, private/public boundaries, phone controls and installed upgrades.
5. Before/after browser state: URL, actual viewport, data, fonts, theme, locale,
   loading completion, relevant motion and screenshot. Inspect the actual result;
   an image's dimensions or a no-overflow check alone cannot establish quality.
6. A separate functionality decision. Recheck every affected journey on the
   specified host after presentation changes. Copy that promises a capability
   must agree with that variant's actual behavior.

For narrow edits, use only affected rows. Do not turn a single wording fix into a
new design direction. Manual semantic/visual review stays a required observation,
not a score inferred from keyword presence or a screenshot hash.
